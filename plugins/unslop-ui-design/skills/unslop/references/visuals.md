# Product-specific visuals

A visual is optional. Dashboards, settings screens, and many app views do not need decorative imagery. Prefer showing the actual product or its data.

## Choose a visual
1. Decide whether a visual materially improves comprehension or product identity.
2. Prefer a real product preview or a single object/scene that belongs to the product's world.
3. Describe the visual in one sentence before creating it.
4. Keep the palette, light, materials, and composition coherent with the page. Leave calm space for text in hero scenes.
5. Avoid generic robots, brains, neon circuits, holograms, glossy blobs, orbs, chrome liquid, floating cubes, and unrelated stock imagery.

## Optional visual directions
Choose only when the product calls for it: a cinematic photograph of one meaningful object; a quiet painted scene; a coherent product-object render; an editorial engraving/print language used consistently; or a restrained data/optics visualization. Do not mix unrelated styles just to add variety.

## Generated imagery
Before any paid generation, present the exact prompt, model/service, expected size, and cost where known, then obtain explicit approval. Use a real image-generation tool if available; do not claim an image was generated if none was. A prompt should specify subject, setting, lighting/palette, style, composition, exclusions (no text/logos/UI/watermarks), and aspect ratio. Save approved assets into the project's assets directory with appropriate dimensions and meaningful alt text.

If no generation tool is available, keep the design functional without the image and provide the prompt as a handoff note. Never insert an empty placeholder that appears production-ready.
